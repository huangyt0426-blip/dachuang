# 微博事件正式采集协议

## 1. 帖子纳入范围

只要帖子出现在已确认的热搜话题检索结果中，就纳入候选帖子表；不因正文情绪或账号类型提前删除。推广、重复和无关内容保留原始记录，并用后续质量字段标记，避免人为选择偏差。

## 2. 帖子排序

每个帖子保存 `repost_count`、`comment_count`、`like_count`，并计算：

`engagement_total = repost_count + comment_count + like_count`

在同一抓取时间截面内按 `engagement_total` 从高到低排序。不得直接使用微博“热门”页面顺序替代计算排序。

同时计算立项书要求的互动比率：

`comment_repost_ratio = comment_count / repost_count`

转发数为 0 时记为空值，并另设零转发标记，不能强行除以 0。

## 3. 传播文本

对排好序的帖子逐帖采集：

- 根帖子正文；
- 一级转发文本；
- 可见的多级转发文本及父节点；
- 一级评论；
- 评论回复及父节点；
- 每个节点的发布时间和可见互动数。

用 `root_post_id`、`node_id`、`parent_node_id`、`depth` 重建级联树，为结构病毒性和传播深度计算提供数据。

## 4. 隐私处理

不在研究表中保存用户名、主页地址、手机号或 Cookie。作者只保留不可逆匿名标识。公开展示或论文附录中的文本需进一步检查是否包含可识别个人信息。

## 5. 抓取顺序

先完成话题所有可见候选帖及互动量快照，再统一排序；随后按排序从第 1 名开始采集转发和评论。不能一边发现帖子一边凭页面顺序采集，否则会产生热度选择偏差。
